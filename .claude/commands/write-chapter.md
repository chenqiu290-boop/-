要写的章节和额外要求：$ARGUMENTS

按顺序执行。主会话只负责调度和核实，不自己通读正文。

1. **确认目标**：从参数取章号 N。用 Glob 确认 `正文/` 下还没有第 N 章文件；已有就停下，问作者是否要改写，不要覆盖。
2. **上一章状态**：用 Grep 查 `大纲/章节状态.md` 是否有第 N-1 章的段落。没有就先调用 `chapter-indexer` 处理第 N-1 章。
3. **写作**：调用 `chapter-writer`，传入章号 N 和作者的额外要求。
4. **检查**：调用 `continuity-checker` 检查第 N 章。
5. **核实**：对检查报告里每一条，回到原文核实（只读被引的那几行）。成立的列入修改清单，不成立的写明理由。
6. **修改**：修改清单非空时，再调用 `chapter-writer`，只按清单改第 N 章。
7. **记录状态**：调用 `chapter-indexer` 处理第 N 章。
8. **汇报**：告诉作者：文件路径、字数、场景顺序、对细纲的调整、采纳和驳回的检查意见、需要同步到人物表／人物小传／细纲／README 的清单（等作者同意再改）。不要自动提交，等作者确认。
